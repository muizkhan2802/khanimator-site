# Khanimator — website

Static multi-page site for **Moiz Khan (Khanimator)**, 2D fan animator.
No build step, no framework, no dependencies. Open the HTML and it runs.

## The catalogue

`data/videos.json` holds all 42 long-form videos with their category, series,
duration, views and thumbnail resolution. It is the **only** place video data
should be edited. After changing it:

```bash
python build.py
```

That regenerates the five category pages. The five hand-written pages are never
touched. Output is plain static HTML — `build.py` is a development tool, not a
runtime dependency.

Categories live at the top of the same file. Adding one means adding a block
under `"categories"`, tagging videos with its slug, re-running the build, and
adding a card to the hub in `work.html`.

### Thumbnails

`build.py` resolves each video's best available thumbnail once and caches the
answer as a `"thumb"` key. This matters: YouTube only generates
`maxresdefault.jpg` for uploads above 720p, and for everything else it serves a
120x90 grey placeholder with **HTTP 200** rather than a 404 — so a client-side
`onerror` fallback never fires. Ten of the older videos hit this. Delete a
`"thumb"` key and re-run to force a re-check.

## Running it locally

Any static server works. From the repo root:

```bash
python -m http.server 5180 --directory khanimator-site
```

Then open `http://localhost:5180`.

### The contact form

Wired to **Netlify Forms** — no code, no third-party service, 100 submissions a
month free. Netlify finds the form by parsing `contact.html` at deploy time, so
the `name`, `data-netlify` attribute and hidden `form-name` input must all stay
put. A honeypot field catches bots. Success redirects to `thanks.html`.

After the first deploy, go to **Site configuration → Forms → Form notifications**
in Netlify and add an email notification, or submissions sit in the dashboard
where nobody looks at them.

Locally the POST has nowhere to go, so `main.js` intercepts it on `localhost`
and shows a note. That check is hostname-based and does nothing once deployed.

## Editing content

**Brand colours and spacing** live in one place — the `:root` block at the top of
`assets/css/style.css`. Change `--accent` and the whole site follows.

**Adding a video** — add an entry to `data/videos.json` and run `python build.py`:

```json
{
  "id": "VIDEO_ID", "title": "…", "duration": "1:23",
  "views": "12K", "viewCount": 12000, "age": "2 months ago",
  "category": "fan-animation", "series": "One Piece", "early": false
}
```

The id is the part after `watch?v=` in a YouTube URL. Omit `"thumb"` and the
build resolves it for you. Thumbnails come straight from YouTube — nothing to
download or host.

The home page and `work.html` carry a hand-picked top five; those are still
edited by hand, on purpose, so the curation doesn't change under you.

## Deploying

Target is **Netlify**, connected to a GitHub repo, deploying on push. There is no
build command — `build.py` runs locally and its output is committed.

### Going live checklist

The site is currently configured to stay **out of search results** while
placeholder copy is on it. Three things must change together to launch:

1. `netlify.toml` — delete the `X-Robots-Tag = "noindex, nofollow"` line.
2. `robots.txt` — swap `Disallow: /` for `Allow: /`, and update the Sitemap URL.
3. `build.py` — set `SITE_URL` to the real domain, re-run the build.

And before flipping those, clear the launch blockers:

- [ ] Real logo at `assets/img/logo.jpg`
- [ ] Patreon tiers confirmed, or the section deleted — **there is a red warning
      banner on `support.html` that must not survive launch**
- [ ] Response time and FAQ answers confirmed
- [ ] "Stories" categorisation confirmed
- [ ] `og:image` in `index.html` changed to an absolute URL on the real domain
- [ ] Email notification configured in Netlify → Forms
- [ ] Sitemap submitted to Google Search Console

## Notes on the build

- **No third-party JS.** YouTube's player is only loaded when someone actually
  clicks a video, and it uses `youtube-nocookie.com`. Nothing tracks the visitor
  on page load.
- **Works without JavaScript.** Content, navigation and layout are all plain HTML
  and CSS. JS adds the reveal animations, the mobile menu and click-to-play.
- **Accessibility.** Skip link, focus-visible outlines, `aria-current` on nav,
  labelled form fields, and `prefers-reduced-motion` honoured throughout.
- **Fonts** are Anton (display) and Inter (body), loaded from Google Fonts. To
  self-host them later, swap the `<link>` tags for local `@font-face` rules.
